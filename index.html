Training Metrics
—
Games ?
Total Games Played
Number of complete self-play games the AI has played against itself. Each game generates training examples from every position visited during MCTS search. More games = more diverse experience in the replay buffer.
—
Buffer ?
Replay Buffer Size
Number of position-policy-value triplets stored for training. Samples are drawn from this buffer during training steps. Max capacity is 100,000 — older examples are evicted when full (FIFO queue).
—
Steps ?
Training Steps
Number of gradient descent updates performed. Each step takes a random batch of 64 examples from the buffer, runs a forward pass, computes policy + value loss, and updates weights via Adam optimizer (lr=0.001).
—
Loss ?
Combined Training Loss
Sum of CrossEntropyLoss (policy) + MSELoss (value) + L2 regularization. Lower = the network better predicts MCTS visit distributions and game outcomes. Starts around 8.0-8.3 (random) and should decrease as the network learns. Not a direct skill metric — it measures fit to its own data.
~200
ELO ?
Estimated ELO Rating
Heuristic estimate: base 200 + log2(games)×80 + log2(steps)×40 + (1-loss)×200. Capped contributions. This is NOT a real ELO — it's a rough proxy. A real rating would require playing rated games against rated opponents (Stockfish, Leela, or human FIDE ratings).
60/40
SF/NN Blend ?
Stockfish / Neural Network Blend
At MCTS leaf nodes, the value signal is a weighted mix: 60% from Stockfish (depth 10, with Gaussian noise σ=0.1) and 40% from the NN's own value head. This guides the network toward engine-quality evaluation while keeping its own judgment in the loop. The NN still generates all move selection priors independently.
